# 사우나고싶다

사우나 → 냉탕 → 외기욕 세트를 3초 만에 기록하고, 내 루틴과 토토노이를 쌓는 기록 앱. 시설 정보는 부가 기능.

## 명령

```bash
npm install
npm run dev          # http://127.0.0.1:3000
npm test             # 하네스 (기록·통계·타이머·피드 규칙)
npm run check        # test + lint + build
npx vercel --prod    # 배포. git push만으로는 배포되지 않는다.
```

## 화면

| 경로 | 역할 |
| --- | --- |
| `/` | 내 기록. 상단 두 버튼(지금 사우나 중 / 다녀왔어요), 이번 달·연속 주·평균 토토노이, 월별 타임라인 |
| `/live` | 사물함 타이머. 폰을 사물함에 넣을 때 입장, 꺼낼 때 퇴장 → '머문 시간'(샤워·탕 포함, 사우나 시간 아님). 세트 수·토토노이는 기억으로 |
| `/live?mode=phases` | 단계별 타이머(폰을 들고 다닐 수 있을 때만). 단계가 바뀔 때 큰 버튼 한 번, 냉탕 뒤 골든타임 2분 |

기록마다 `source`로 어떻게 잰 건지 남긴다: manual(기억) · locker(머문 시간 측정) · timer(단계별 측정) · watch(워치, 예정). 세트당 시간이 실측인 건 timer·watch뿐이고 나머지는 루틴 기반 추정이다. CSV의 `sets_measured`로 학습 때 가중치를 나눈다.

마이: 월간 요약(달 넘기기), '무엇이 토토노이를 올렸나'(조건 있을 때/없을 때 평균 차이, 양쪽 3회 이상만), 내 루틴 vs 책, 나올 맥박(안정시 심박 ×2, 아침 110·밤 130 상한, 기기에만 저장). 기록에 외기욕 자세·장소(선택)와 '평소보다 짧게/길게'가 남아 비교 조건이 된다.
| `/new` | 빠른 기록. 최근 장소·내 루틴이 미리 채워져서 토토노이 하나 누르고 저장. `?edit=id`로 수정, `?place=id`로 시설에서 진입 |
| `/feed` | 공개 기록 피드. 별점·랭킹 없음 |
| `/saunas`, `/saunas/[id]` | 인허가 시설 검색. 시설 숫자는 "기록 N개 기준" 중앙값만 |
| `/me` | 누적, 6개월, 내 루틴 vs 『사우나 교과서』, CSV 내보내기 |

## 규칙이 사는 곳

UI는 규칙을 다시 만들지 않는다. 화면은 `src/harness/`만 호출한다.

| 경로 | 역할 |
| --- | --- |
| `src/harness/records.ts` | 기록 검증, 루틴(중앙값), 통계, 시설 통계, 타이머(누른 시각 → 세트), 피드 병합, CSV |
| `src/harness/community.ts` | 브라우저 상태 v3, v2(방문) → v3(기록) 이전 |
| `src/harness/community.test.ts` | 위 규칙의 테스트 (`npm test`) |
| `src/app/api/records/route.ts` | 공개 기록 피드 GET/POST(upsert·like·delete) |
| `src/server/store.ts` | 피드 저장 (파일 JSON). KV로 바꾸려면 `readFeed`/`writeFeed`만 |
| `src/data/places.ts`, `facilities.ts` | LOCALDATA 목욕장업 → `Place` (이름·종류·지역·주소·전화만) |

## 데이터 원칙

- 내 기록은 브라우저(localStorage)에 저장. "피드에 공개"를 켠 기록만 서버로 간다.
- 온도·요금·영업시간은 인허가에 없으면 지어내지 않는다. 예전 대표 시드 24곳과 시드 방문 글은 데모 값이라 지웠다.
- 스톡 사진을 쓰지 않는다.
- 권장 시간은 『의사가 가르쳐 주는 사우나 교과서』 기준 안내값. 의학 조언 아님.
